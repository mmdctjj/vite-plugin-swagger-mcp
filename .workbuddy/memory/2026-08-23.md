# 2026-08-23

## MCP SDK v1 → v2 迁移（修复编辑器无法连接）

**根因**：`@modelcontextprotocol/sdk` 单包停留在 v1 线（最终 1.30.0），不再跟进 2026-07-28 新协议；官方 v2 拆分为 `@modelcontextprotocol/server` + `/client` + `/core`（2.0.0 已稳定）。新版 VSCode/Cursor/Windsurf/Claude Code 走新协议/Streamable HTTP 单端点，v1 服务端握手不兼容。

**改动**：
- `package.json`：移除 `@modelcontextprotocol/sdk`，新增 `@modelcontextprotocol/server ^2.0.0` + `@modelcontextprotocol/node ^2.0.0`，zod `^3.25.76` → `^4.2.0`
- `src/index.ts`：`import { McpServer } from "@modelcontextprotocol/server"`、`import * as z from "zod/v4"`、`tool()`→`registerTool(name, {description, inputSchema: z.object(...)}, handler)`
- HTTP 挂载：弃用手写 `StreamableHTTPServerTransport` + sessionIdGenerator，改用 v2 推荐的 `createMcpHandler(factory)`（每请求工厂，天然多客户端）+ `toNodeHandler()` 适配 Vite connect
- `README.md`：端点改为 `/_mcp/swagger`（新协议单端点，兼容旧客户端），补 Node ≥ 20

**关键坑**：
1. v2 不能复用单例 transport（会报 "Server already initialized"），必须用 `createMcpHandler(() => new McpServer(...))` 工厂模式
2. v2 是 ESM-only、要求 Node ≥ 20
3. registerTool 的 inputSchema 用 Standard Schema（zod v4 object），不再是 v1 的 raw shape

**验证**：
- `pnpm build`（father）ESM+CJS 均通过；`tsc --noEmit` 无错误
- 本地 vite dev server 挂插件，curl 实测：
  - 客户端 A 用 2025-11-25 协议 initialize → 200 + serverInfo
  - 客户端 B 用 2026-07-28 协议 initialize → 200（双协议协商 OK）
  - tools/list 列出 getModules/getModuleApis/getApiTypes 3 个工具
  - tools/call getModules / getModuleApis 返回正确数据
